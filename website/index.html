Documentation built from the source tree

Build the web in a language that reads like the interface.

JGrandson is an experimental language for describing interfaces, behavior, server routes, and AI tools in .jg files. It includes a compiler, semantic analyzer, CLI, Vite workflow, language server, and multiple output backends.

Build your first page → Explore the language

Project maturity

JGrandson is a preview language under active development. React output and the local development workflow are established. Native web, backend, AI, and advanced compiler analysis exist in varying stages and are marked clearly throughout these docs.

01 · Get started

Install the toolchain

JGrandson currently requires Node.js 18 or newer. Inside this repository, install dependencies and build all workspace packages before running the CLI.

Terminal
$ npm install
$ npm run build
$ npx jg --version
jgrandson v0.1.0

Once the npm packages are publicly available, the intended global installation is:

npm install --global @jgrandson/cli
02 · Tutorial

Your first .jg app

Create a page with local state and a button. The structure, state, content, and event live together without JSX or hook ceremony.

src/App.jg
page Counter {
  state {
    count: number = 0
  }

  main {
    h1 {
      text { content: "Count: " + count }
    }

    button {
      text: "Increase"
      onClick { count++ }
    }
  }
}

04 · Language

A compact language tour

A program contains imports followed by pages, components, functions, types, interfaces, routes, or tools. Newlines separate most declarations and statements.

P

Pages

page Home { ... }

Top-level interface entries selected by the build or router.

C

Components

component Card(title: string)

Reusable, typed interface units with children and named slots.

ƒ

Functions

function add(a, b): number

Typed reusable logic, including async functions and error handling.

T

Types

type Result = Data | null

Primitive, array, union, object, alias, and interface types.

05 · Composition

Components and slots

Component parameters are typed and may be optional or defaulted. An unnamed slot receives normal children; named slots model areas such as actions or footers.

Card.jg
component Card(title: string, tone?: string = "calm") {
  article {
    h2 { text { content: title } }
    slot {
      text { content: "No content supplied" }
    }
    slot(actions) {}
  }
}

page Home {
  Card("Welcome") {
    text { content: "Build something clear." }
    slot(actions) { button { text: "Continue" } }
  }
}
06 · Interaction

State and events stay close to the UI

Built-in handlers include onClick, onInput, onChange, onSubmit, onFocus, and onBlur. Input handlers can capture their value directly.

Search.jg
page Search {
  state { query: string = "" }

  input {
    value: query
    onInput(value) { query = value }
  }

  text { content: "Searching for: " + query }
}
A
Accessibility is part of analysis

The semantic checker reports missing image alternatives and unnamed buttons. More complete UX contracts are being developed in the compiler track.

08 · Full stack

09 · AI

AI tools with boundaries

Preview

AI is designed as a server capability. The repository contains provider-neutral message, provider, tool, and agent interfaces, plus early checks for consequential actions, fallbacks, and data provenance.

knowledge-agent.jg
tool searchKnowledge(query: string) {
  return "Knowledge result: " + query
}

route POST "/api/chat"(prompt: string) {
  return searchKnowledge(prompt)
}
!
Server-side by design

Provider credentials and consequential tool execution belong on the server. The roadmap requires validation, permissions, budgets, tracing, fallback behavior, and human approval where appropriate.

12 · Internals

Compiler architecture

Source locations survive the pipeline so diagnostics can point back to the original file. Target-specific behavior belongs in compiler backends while parsing, analysis, formatting, and editor features remain shared.

  1. 01
    Lexer

    Turns UTF-8 source into tokens with one-based line and column locations.

  2. 02
    Parser + AST

    Builds declarations, statements, expressions, elements, routes, and tools.

  3. 03
    Semantic analyzer

    Resolves symbols, types, modules, target boundaries, accessibility, provenance, effects, workflows, and lint rules.

  4. 04
    Compiler backends

    Generate React/TypeScript, native HTML/DOM output, or server artifacts.

  5. 05
    Developer tools

    CLI, Vite plugin, language server, formatter, VS Code extension, and tests share the same language model.

15 · Direction

The path to 1.0

The roadmap orders work by dependency. Native output sits before the AI and deployment milestones so later features can rely on a stable browser model.

0.1–0.5
Language and tooling foundation

Core correctness, project workflow, language completeness, editor tooling, and release preparation.

0.6
Backend and data runtime

Routes, boundaries, middleware, databases, jobs, clients, and observability.

0.7
Native web compiler

Typed IR, direct HTML/CSS/DOM output, fine-grained updates, incremental builds, and performance gates.

0.8–0.9
AI and deployment

Typed model capabilities followed by reproducible full-stack deployment.

0.10–0.16
Special compiler track

Explainability, provenance, effects, budgets, workflows, AI authority, replay, UX contracts, and visual editing.

1.0
Stable language

Frozen core semantics, compatibility policy, audits, migration tools, and substantial reference applications.

17 · Help

Common problems

jg: command not found+

Use npx jg from a project with the CLI installed, or ensure the global npm binary directory is on your PATH.

The development server does not start+

Check whether another process is using port 5173, then run jg clean to remove generated preview state before retrying.

The editor and CLI report different errors+

Use matching versions of the VS Code extension and @jgrandson/cli in the workspace, then restart the language server.

Lighthouse reports huge development JavaScript+

Measure a production build. Vite development mode includes the client, React development code, source maps, and refresh diagnostics.
